**Исследовательский инструмент для биометрической идентификации голоса и акустического анализа, объединяющий нейросетевые технологии и классическую цифровую обработку сигналов (DSP).**

---

## 📖 О проекте

**TVE** — это десктопное приложение (WPF), разработанное в рамках научно-исследовательской работы. Оно решает задачи распознавания речи, идентификации говорящего и математического анализа акустических характеристик голоса (F0, гармоники, форманты).

В отличие от классических реализаций (чистый DSP на Go или только нейросети на Python), в данном проекте используется **гибридный подход**.

---

## ✨ Основные возможности

- 🎤 **Запись и VAD**: Захват аудио с микрофона с автоматическим отсечением тишины (RMS-порог).
- 🗣 **Распознавание речи**: Локальная нейросеть **Whisper.net** (модель `ggml-base`).
- 🧬 **Идентификация голоса**: Извлечение 512-мерных эмбеддингов через **ERes2Net-Base** (sherpa-onnx).
- 📈 **Продвинутая математика**:
  - Обновление профиля методом **SLERP** (сферическая интерполяция).
  - Margin-проверка для защиты от ложных срабатываний.
- 🎛 **DSP-анализ**: Извлечение F0 тремя независимыми методами (Кепстр, HPS, Автокорреляция), поиск гармоник (k1-k8) и формант (F1-F4 через LPC).
- 📊 **Визуализация**:
  - Карта голосов (PCA + K-Means + Convex Hull).
  - Матрица косинусных сходств.
  - Спектрограммы и графики слияния эмбеддингов.
- 📁 **Импорт/Экспорт**: Поддержка Drag-and-Drop аудиофайлов и экспорт данных в CSV.

## 🛠 Технологический стек

### Core & UI
- **Язык**: C# 13
- **Платформа**: .NET 10, WPF (Windows Presentation Foundation)
- **Архитектура**: Разделение на библиотеку классов (`TVE.Core`) и интерфейс (`TVE.Ui`)

### Нейросети и Математика
- **Whisper.net** — распознавание речи (OpenAI, 2022)
- **sherpa-onnx** — извлечение эмбеддингов (Alibaba 3D-Speaker, 2022)
- **NAudio** — захват и обработка аудиопотока
- **LiteDB** — встроенная NoSQL база данных
- **OxyPlot** — построение графиков

1. Архитектура и ядро (TVE.Core)
1.1. Захват аудио и VAD (Audio/MicrophoneCapture.cs)
Класс MicrophoneCapture отвечает за получение звука с микрофона.

Метод Start(): использует WaveInEvent из библиотеки NAudio. Настраивает формат: 16 кГц, моно, 32-битный float.

Алгоритм VAD (Voice Activity Detection): внутри события OnDataAvailable вычисляется RMS (среднеквадратичное значение) для каждого буфера (50 мс). Если RMS > 0.01, считается, что идет речь. Если тишина длится более 800 мс, сегмент завершается и отправляется на обработку.

Watchdog: таймер, который раз в 2 секунды проверяет, подключен ли микрофон, чтобы программа не зависла при отключении USB.

1.2. Проверка качества (Audio/SegmentQualityChecker.cs)
Прежде чем отдать звук нейросети, он проверяется:

Длина: минимум 400 мс.

Громкость: RMS должен быть больше 0.008.

Проверка на два голоса: если сегмент длинный (больше 3.5 сек), он делится пополам. Считаются эмбеддинги для каждой половины. Если косинусное сходство между ними < 0.55, значит, в комнате говорят два человека, и звук отбрасывается.

1.3. Распознавание речи (Recognition/WhisperRecognizer.cs)
Обертка над Whisper.net.

Метод TranscribeAsync(): принимает массив сэмплов, прогоняет через нейросеть (модель ggml-base.bin) и возвращает текст.

Внутренний алгоритм Whisper: аудио переводится в Mel-спектрограмму (через STFT и Mel-фильтры), затем Encoder-Decoder Transformer генерирует токены (слова) одно за другим на основе вероятностей.

1.4. Эмбеддинги (Speaker/VoiceEmbedder.cs)
Обертка над sherpa-onnx.

Метод Extract(): принимает аудио, создает поток (CreateStream), передает данные в модель ERes2Net-Base. На выходе — вектор из 512 чисел (float).

Почему это работает: модель обучена (через ArcFace) так, чтобы векторы одного человека были близки (косинусное сходство > 0.8), а разных — далеки (< 0.3).

1.5. База данных (Storage/VoiceDatabase.cs)
Работа с LiteDB (NoSQL).

Коллекции: speakers (говорящие) и utterances (реплики).

Метод FindClosestSpeaker(): главный алгоритм идентификации.

Перебирает всех спикеров в базе.
Считает косинусное сходство: sim = (a · b) / (||a|| * ||b||).
Сортирует результаты.
Двойная проверка: лучший результат должен быть > 0.55 (порог) И отрываться от второго места на 0.05 (margin). Если margin маленький — программа честно говорит «не знаю» и создает нового пользователя, чтобы избежать ошибки.
1.6. DSP-анализ (Analysis/HarmonicAnalyzer.cs)
Классическая математика для научных исследований.

Поиск F0: делается тремя способами — Кепстр (Cepstrum), Гармонический спектр (HPS) и Автокорреляция. Результаты голосуются, чтобы отсечь октавные ошибки (когда алгоритм путает F0 и 2*F0).

Поиск формант (F1-F4): используется метод линейного предсказания (LPC) 22-го порядка. Это позволяет выделить резонансные частоты речевого тракта (гортани, рта), которые уникальны для каждого человека.

Спектрограмма: строится через быстрое преобразование Фурье (FFT) с окном Ханна.

1.7. Математика для визуализации (Analysis/)
PCA (Principal Component Analysis): метод главных компонент. Сжимает 512-мерные векторы до 2D, чтобы их можно было нарисовать на экране, сохраняя максимум информации о различиях.

K-Means: алгоритм кластеризации (разбивает точки на группы похожих голосов).

SLERP (Spherical Linear Interpolation): сферическая интерполяция. Используется для «умного» обновления эмбеддинга в БД. Вместо простого сложения (которое уводит вектор внутрь сферы) мы движемся по дуге между старым и новым вектором.

2. Пользовательский интерфейс (TVE.Ui)
2.1. Главное окно (HomeView.xaml)
Круглая кнопка: запускает/останавливает запись.

Панели слева/справа: показывают, кто говорит (имя, описание) и выводят распознанный текст в реальном времени.

Drag-and-Drop: если перетащить на круг аудиофайл (MP3, WAV и т.д.), программа нарежет его на сегменты, распознает и запишет в БД.

2.2. Голоса в базе (VoicesView.xaml)
Таблица всех пользователей. Можно менять имена (inline-редактирование), писать описания (открывается окно DescriptionWindow), смотреть историю реплик (HistoryWindow).

Сортировка: можно сортировать по имени, дате или количеству реплик.

2.3. Анализ (AnalysisWindow.xaml)
Окно с вкладками для глубокого изучения данных.

Матрица сходства: таблица, где показано, насколько каждый голос похож на остальные (от 0 до 1). Красный — очень похожи, зеленый — разные.

Карта голосов: визуализация 512-мерных векторов на 2D-плоскости. Показывает кластеры (группы похожих голосов). Точки соединены линиями, если их сходство выше порога.

Гармоники: окно HarmonicAnalysisWindow с графиком спектра, где отмечены пики (гармоники) и форманты. Позволяет увидеть, как меняется голос при изменении интонации.

Слияние эмбеддингов: показывает, как новый голос «вливается» в профиль пользователя (визуализация SLERP).

2.4. Настройки (SettingsView.xaml)
Выбор микрофона, темы (светлая/темная), путь к базе данных, экспорт/импорт БД.
